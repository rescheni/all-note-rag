## 1. 产品定位与边界

笔记中枢（Note Hub）是个人笔记与团队文档的只读聚合层。Notion、飞书（Lark）、思源笔记（SiYuan）、Obsidian 继续作为编辑器存在，本系统不替代它们。中枢负责四件事：

1. **接入（Ingest）**：从各源把可读内容同步到本地缓存与 S3 规范对象。
2. **预览（Preview）**：只读渲染规范 Markdown，带块级锚点。
3. **问答（Q&A）**：基于检索的问答，必须返回可跳转到预览块锚点的来源卡片。
4. **成长分析与可安装 Skills**：个人空间上的成长事件统计；Skills 是可安装的 `SKILL.md` 包。

个人笔记与团队文档共用同一套数据模型，用 **Space** 隔离。`Space.kind` 仅为 `personal` 或 `team`。

### 1.1 v1 硬性边界

- 中枢是 **只读聚合**。不写回任何源。写回永久不在范围内，除非另出新规格。
- 预览 **只读本地缓存 / S3 规范对象**，禁止在预览路径上调用源站实时 API。
- 问答必须引用来源卡片，卡片跳转到预览页的块锚点。
- 成长分析（`GrowthEvent`）**仅个人空间**。团队空间只做覆盖率 / 贡献度，不产生、不查询 `GrowthEvent`。
- Skills 是可安装包：一个目录，内含 `SKILL.md` 与可选脚本，语义对齐助手 Skills。

## 2. 术语

| 术语 | 含义 |
|------|------|
| Space | 隔离单元。`kind=personal` 或 `kind=team`。一条 Connection 属于一个 Space。 |
| Connection | 到某一源的连接配置（凭证、游标、模式、状态）。 |
| Note | 一篇规范化后的笔记。`source_id` 稳定，移动/重命名只改 `path`/`title`。 |
| Block | Note 内的块。预览锚点为 `id=b-{source_block_id}`。 |
| Canonical | S3 上该 Note 的规范对象：`note.md` + `meta.json` + `assets/`。 |
| Source mirror | S3 上源原生镜像，按源格式原样存放。 |
| Skill | 可安装包。目录 + `SKILL.md` + 可选脚本。由 `skill-runner` 隔离执行。 |
| GrowthEvent | 仅个人空间的成长事件（goal / habit / mood / review / focus）。 |

## 3. 源系统接入规格

v1 四个源。实现顺序见第 16 节：P0 只做 Obsidian 明文前缀，不要先并行做四个适配器。

### 3.1 Obsidian（S3，Remotely Save 风格）

**权威存储**：用户自己的 S3（或兼容）桶。对象键：

```
{remotePrefix}/{vault 相对路径}
```

文件为明文 Markdown + 附件，**除非**插件开启了 E2EE。

**增量**：`ListObjectsV2` + `ETag`。`LastModified` 精度只有秒，不能单独作为变更判据；以 ETag（及对象键集合差）为准。

**默认忽略**：

- `.obsidian/`
- `.trash/`

**E2EE**：若探测到加密（连接配置 `e2ee=true`，或对象呈现密文包装），将该 Connection 标为 `encrypted_unreadable`，**不摄入正文**，同步任务记警告后跳过。

**source_id**：

```
obsidian://<connection_id>/<posix vault path>
```

示例：`obsidian://conn_01HX/Daily/2026-08-29.md`

重命名或移动：同一逻辑文件若路径变了，视为 **path/title 更新**，`source_id` 按新路径重算。因路径即身份，旧 `source_id` 对应行做软删除，新路径 upsert。若后续官方插件提供稳定 file id，另开规格；P0 不阻塞。

**规范化**：vault 内 `.md` → Note；同目录及约定附件目录中的二进制 → Asset；Wiki-link `[[...]]`、Markdown 链接、embed `![[...]]` → Link。

### 3.2 思源笔记（SiYuan）

**权威工作区在磁盘上的 `data/`，不是官方 S3 同步。**

官方思源 S3 提供方把加密的 dejavu 快照块写在 `repo/` 下。v1 **禁止解包**。产品文案必须写明「官方 S3 同步不受支持」，并引导用户使用模式 A 或模式 B。

#### 3.2.1 模式 A（推荐路径；实现排期 P2 必做）

走思源内核 HTTP API（自托管或本机）。使用：

- 笔记本列表
- 文档树
- 导出 Markdown，或块 API

加密笔记本仅在内核解锁后可读。Worker 如何打到本机内核列为开放项，不阻塞 P0。产品上推荐模式 A；按第 16 节，P2 必须交付模式 A。

#### 3.2.2 模式 B（明文工作区对象）

用户把可读的工作区 `data/`（或整个工作区）以明文对象同步到中枢可读位置。按下面布局解析。加密笔记本：跳过并告警。

#### 3.2.3 工作区布局（模式 B 解析规则）

| 路径 | 含义 |
|------|------|
| `data/<boxID>/` | 一个笔记本。`boxID` 是 NodeID，格式 `YYYYMMDDHHMMSS-xxxxxxx`。 |
| `data/<boxID>/<docID>.sy` | 一篇文档。文件名 = 文档 rootID。 |
| `data/<boxID>/<docID>/` | 该文档的子文档目录，可任意嵌套。 |
| `data/assets/` | 全局资源。 |
| `data/<boxID>/assets/` | 加密笔记本的每本资源目录。 |
| `data/<boxID>/.siyuan/conf.json` | 笔记本显示名在字段 `name`。笔记本 ID 是目录名，**不在** conf.json 里。 |
| `temp/*.db` | 可重建索引，**永远不当作源**。 |

HPath 由祖先 `.sy` 的 title 推导，不落盘。

`.sy` 是块树 JSON，不是 Markdown。必须实现 `syToMarkdown`。块引用 `((id))` 保留为 Links。**不要猜测节点类型**；实现时对照官方 SY-FORMAT 夹具（fixture）。

**source_id**：文档 rootID（`.sy` 的文件名，不含扩展名）。

**P2 验收**：模式 A 必做；模式 B 加分为佳；官方 S3 dejavu 必须在 UI / 文档中明确标为不受支持。

### 3.3 Notion

- 鉴权：OAuth（公开集成，`NOTION_CLIENT_ID` / `NOTION_CLIENT_SECRET` / `NOTION_REDIRECT_URI`）。未配置或用户选择时，可用 Integration Token 作为后备；适配器优先 `access_token`，否则 `token`。
- 增量：`search` + `last_edited_time`。
- Database：Database 页本身是一篇 Note；每一行也是一篇 Note；属性写入 frontmatter。此为 v1 模型，不在 v1 做关系型看板。
- 正文：`blocks.children.list`，遵守官方速率限制。
- ACL v1：能被 search 搜到的，即在该 Space 内可见。文档级 ACL 放到 P4。

**source_id**：`page_id`。

### 3.4 飞书（Feishu / Lark）

- 鉴权：自建应用 `app_id` / `app_secret` 换 `tenant_access_token`（内部接口）。v1 **不要求** `user_access_token`。
- Wiki v2：`spaces/:id/nodes`。增量字段：`obj_edit_time` / `revision_id`。
- 内容身份是 **`obj_token`**，不是 `node_token`。用 `obj_type` 选择 docx API。
- v1 只摄入 **docx / wiki-docx**。Sheet / Bitable 作为附件或属性摘要，不解析单元格为 Note。
- 一个团队 Space 映射一个飞书知识空间。
- **通讯录同步**（团队空间）：用同一套应用凭证调 contact v3（部门树 + `users/find_by_department`）。按 **邮箱**（`email` 或 `enterprise_email`，小写）匹配已注册中枢用户；无邮箱或邮箱未注册则跳过，**不自动创建账号、不编造口令**。`open_id` 仅用于去重，不落用户表。命中且尚非成员的，以默认角色 **`viewer`** 幂等插入 `space_members`（`ON CONFLICT (space_id, user_id) DO NOTHING`）。已有成员（含 owner / editor / 手工加入）角色不变；不同步删除。个人空间仍仅 owner，通讯录同步不加第二成员。手动 `POST /v1/connections/:id/contacts/sync`；飞书文档同步成功后也会跑一轮。

**source_id**：`obj_token`。

## 4. S3 中枢桶布局

环境桶名：`hub-{env}`，`env ∈ {dev, staging, prod}`。本地开发用 MinIO，前缀相同。

```
s3://hub-{env}/source/{space_id}/{connection_id}/     # 源原生镜像
s3://hub-{env}/canonical/{space_id}/{note_id}/note.md
s3://hub-{env}/canonical/{space_id}/{note_id}/meta.json
s3://hub-{env}/canonical/{space_id}/{note_id}/assets/
s3://hub-{env}/preview/{space_id}/{note_id}/{hash}.html
s3://hub-{env}/skills/{skill_id}@{version}/
```

规则：

- `source/` 按源格式原样存放（Obsidian 的 md、思源的 `.sy`、Notion/飞书的原始 JSON）。预览与问答 **不读** `source/`。
- `canonical/note.md` 是唯一规范化正文。`meta.json` 至少含：`note_id`、`source_id`、`connection_id`、`space_id`、`title`、`path`、`hash`、`updated_at`、`block_index`。
- `preview/{hash}.html` 的 `hash` 与 canonical `note.md` 的内容哈希一致；哈希未变则不重渲。
- Skills 包以 `skill_id@version` 不可变存放。启用时只读该前缀。

`meta.json` 形状：

```json
{
  "note_id": "uuid",
  "source_id": "obsidian://conn_01HX/Daily/2026-08-29.md",
  "connection_id": "uuid",
  "space_id": "uuid",
  "title": "2026-08-29",
  "path": "Daily/2026-08-29.md",
  "hash": "sha256-hex",
  "updated_at": "2026-08-29T10:00:00Z",
  "block_index": [
    { "source_block_id": "...", "type": "heading", "order_key": "a0" }
  ]
}
```

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | uuid | PK | |
| space_id | uuid | FK Space, not null | **必须** `spaces.kind = personal`，用触发器或应用层双检 |
| user_id | uuid | FK User, not null | |
| note_id | uuid | FK Note, nullable | |
| kind | text | not null, check in (`goal`,`habit`,`mood`,`review`,`focus`) | |
| happened_at | timestamptz | not null | |
| payload | jsonb | not null default `{}` | |
| created_at | timestamptz | not null | |

查询层 **必须** 硬过滤：`GrowthEvent` 只查 `kind=personal` 的 Space。团队笔记不得漏入成长分析。团队空间可另做覆盖率 / 贡献度查询（基于 Note / Link / SpaceMember），不写本表。

建议触发器：

```sql
CREATE OR REPLACE FUNCTION growth_personal_only() RETURNS trigger AS $$
BEGIN
  IF NOT EXISTS (
    SELECT 1 FROM spaces s WHERE s.id = NEW.space_id AND s.kind = 'personal'
  ) THEN
    RAISE EXCEPTION 'GrowthEvent only allowed on personal spaces';
  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

### 5.11 source_id 规则

| 源 | source_id | 重命名 / 移动 |
|----|-----------|----------------|
| Obsidian | `obsidian://<connection_id>/<posix vault path>` | 只更新 path/title；因路径即身份，旧行软删、新路径 upsert |
| 思源 | 文档 rootID（`.sy` 文件名） | 只更新 path/title，source_id 不变 |
| Notion | `page_id` | 只更新 path/title |
| 飞书 | `obj_token` | 只更新 path/title |

`source_id` 在同一 Connection 内稳定。禁止用 title 当身份。

### 5.12 同步日志表（P0 必建）

**sync_run**：`id, connection_id, started_at, finished_at, upserts, deletes, skipped, failed, cursor_before, cursor_after`。

**sync_note_log**：`id, connection_id, source_id, note_id, level, message, created_at`。单篇失败写这里，不中止整批。

## 7. 适配器接口

`packages/adapters` 对每个源实现同一接口。实现时以 `packages/core` 导出的类型为准。

变更类型只有两种：`upsert` 与 `delete`。

```
Change = {
  type: upsert | delete,
  source_id: string,
  path?: string,
  etag?: string,
  source_updated_at?: string  // ISO 8601
}

AdapterContext = {
  connection,   // secrets 仅在 worker 内存，不打日志
  cursor
}

NotePayload = {
  source_id, path, title,
  raw,          // 源原生字节或结构
  assets?,
  acl?
}

Adapter = {
  probe(ctx) -> { ok, status?, message? }
  listChanges(ctx) -> { changes, nextCursor }
  fetchNote(ctx, source_id) -> NotePayload | null
  fetchAsset(ctx, ref) -> bytes
  resolveAcl?(ctx, source_id) -> acl
}
```

规则：

- `listChanges` 必须可恢复：成功处理完全部 change 后才写回 `Connection.cursor`。中途失败保留旧 cursor，允许重复 upsert（幂等靠 hash）。
- `fetchNote` 返回 `null` 视为源侧已消失，按 delete 处理。
- `resolveAcl` 可选。v1 Notion：能 search 到即可见。飞书 / Obsidian / 思源：可见性等于 Space 成员。
- 适配器禁止写数据库、禁止写 `canonical/`。只读源。写 `source/` 镜像由管道调用方完成。
- `probe` 可把连接标为 `encrypted_unreadable`（Obsidian E2EE）或 `error`。

## 8. 同步管道

触发到落库的固定顺序：

```
tick | webhook | S3 event
        ↓
   listChanges
        ↓
   对每个 Change:
        fetchNote / 确认 delete
        ↓
   写入 source/ 镜像
        ↓
   normalize（packages/normalize）
        ↓
   hash 相同 → 跳过后续
        ↓
   写 canonical/ + upsert 数据库（Note / Block / Asset / Link）
        ↓
   入队 preview.render、embed.chunk、skill hook（post-sync）
```

细则：

1. **触发**：P0 用 api 定时 tick（默认 5 分钟）+ 手动 `POST /v1/connections/:id/sync`。S3 事件放到 P4。Webhook（Notion / 飞书）P3 可接，未接时仍靠 tick。
2. **镜像**：先把源原生对象写入 `s3://hub-{env}/source/{space_id}/{connection_id}/...`，再规范化。镜像失败则该 Note 失败，不写 canonical。
3. **hash**：对规范化后的 `note.md`（含 frontmatter 的稳定序列化）做 sha256。与 `Note.hash` 相同则跳过 canonical 覆盖、预览、嵌入。
4. **软删除**：`Change.type=delete` 或 `fetchNote=null` → `Note.deleted_at=now()`；Block / Chunk / Link 随 Note 删除或标记。S3 canonical 保留直到垃圾回收（P0 可先留着）。
5. **并发**：同一 Connection 串行跑 `listChanges` 批次；不同 Connection 并行。单篇 Note 失败写入 `sync_note_log`，**不中止整批**。
6. **Connection 状态**：探活失败或 E2EE → `encrypted_unreadable` / `error`。单篇失败不把整个 Connection 打成 error，除非 `probe` 失败。
7. **post-sync hook**：本批至少一篇 hash 变化才入队。Skill 只读 canonical 与数据库，见第 12 节。

`sync_note_log` 与 `sync_run` 在 P0 必须建好，便于验收「15 分钟内更新」。

同一 Connection 的同步任务用固定 job id（`sync:{connection_id}`）去重，禁止并行跑两轮。`sync.note` 在同一连接内默认并发 4。`preview.render` 默认并发 8。`embed.chunk` 默认并发 4。`skill.hook` 默认并发 2。

## 9. 规范化（normalize）

输入：源原生 + Connection 元数据。输出：

- `note.md`（UTF-8，可选 YAML frontmatter）
- `meta.json`
- `blocks[]`
- `links[]`
- `assets[]`（字节写入 `canonical/.../assets/`）

公共规则：

- 不执行笔记内任何脚本，不渲染自定义 code widget。
- 块引用、双向链接变成 `Link`。Markdown 里保留可点击的中枢内链：`/n/{note_id}#b-{source_block_id}`（目标未解析则保留原文 + `to_source_id`）。
- frontmatter 键名小写。Notion 属性名原样进入 frontmatter。
- 思源：`syToMarkdown`；`((id))` → Link（`kind=ref`）；节点类型以 SY-FORMAT 夹具为准，禁止猜测。

Obsidian Wiki-link 解析顺序：同目录相对路径 → vault 内唯一文件名 → 失败则 `to_note_id` 为空。

哈希稳定序列化（算 hash 之前）：UTF-8，LF 换行，frontmatter YAML 键排序，文末恰好一个换行。避免无意义重渲、重嵌。

## 10. 预览

- **只读** `preview/` 与 `canonical/`。禁止为了预览去打源 API。
- 渲染器在 `packages/preview`：markdown-it + 有限插件（GFM 表、任务列表、代码高亮）。附件用 canonical `assets/` 的短 TTL 签名 URL。
- 块锚点：每个块根节点带 `id=b-{source_block_id}`。问答来源卡片 URL：

```
/spaces/{space_id}/notes/{note_id}/preview#b-{source_block_id}
```

- **禁止**执行笔记脚本、禁止任意源 iframe、禁止未消毒 HTML。sanitize 后输出。
- `hash` 未变则复用已有 HTML 对象。
- Web 预览页从 api 取签名 URL 或由 api 代理 HTML，仍不得回源。

## 11. 检索与问答

### 11.1 检索

顺序固定：

1. **ACL / Space 过滤（硬）**：当前用户是该 Space 成员；`Note.deleted_at IS NULL`；再按 `note_visible_to(acl_snapshot, user_id, role)` 过滤。空间可见的笔记所有成员可读；`owners` 仅所有者；`members` 仅名单内成员（所有者始终可读）。列表、树、搜索、问答、预览、附件同一套。成长相关检索再叠加「仅 personal」。
2. **FTS + 向量 + 1-hop 图** 三路召回。
3. **RRF** 融合。
4. **可选 rerank**（P4 打开，v1 默认关）。

切块：

- 按 heading 切。目标 400–800 token / chunk。过短合并到下一 heading，过长按段切并保留同一 `heading_path`。
- 思源按块边界切，不把一个思源块劈开；超长块按段二次切，但 `block_id` 仍指向源块。

1-hop 图：从命中 Note 出发，经 `Link.kind ∈ {ref, embed}` 走到相邻 Note 的 chunk，降权纳入 RRF。

无检索命中：问答必须回答「未知 / 笔记中未找到」，禁止臆造。

### 11.2 FTS 与中文

P0 使用 Postgres FTS。中文分词风险见第 17 节。P0 最低要求：

- 使用可用的中文文本搜索配置（优先 zhparser 或 pg_jieba 之一；镜像里都没有时，退回 `simple` + 双gram 表达式索引，并在风险表跟踪）。
- `Chunk.fts` 与 `Note.title` 加权。搜索 API 返回 Note 级结果，高亮用 chunk 片段。

P0 验收只要求「改一篇 md 后 15 分钟内能搜到新词」，不要求召回率指标。

### 11.3 Ask API

`POST /v1/spaces/:space_id/ask`

请求：

```json
{
  "query": "本周我写过哪些关于睡眠的回顾？",
  "note_ids": [],
  "skill_hint": null
}
```

响应必须含 `citations`：

```json
{
  "answer": "...",
  "unknown": false,
  "citations": [
    {
      "note_id": "...",
      "title": "...",
      "space_id": "...",
      "source_block_id": "...",
      "preview_url": "/spaces/.../notes/.../preview#b-...",
      "quote": "原文片段"
    }
  ]
}
```

规则：

- 每条引用对应一个预览块锚点。前端来源卡片只跳 `preview_url`。
- 检索 0 命中：`unknown=true`，`answer` 为固定中文「在当前空间的笔记里没有找到依据。」，`citations=[]`。
- 生成模型只看到检索到的 chunk + 引用元数据。提示词禁止无引用作答。
- `on-ask` Skill 可在生成前后改写 query 或补充卡片，但不能去掉引用约束，也不能携带源凭证。

P0 不做 Ask。P1 做。

## 12. Skills

Skills 是可安装包，不是提示词片段。目录结构：

```
SKILL.md
scripts/            # 可选
references/         # 可选
```

对象键：`s3://hub-{env}/skills/{skill_id}@{version}/`

### 12.1 SKILL.md

文件开头 YAML frontmatter，随后 Markdown 说明。v1 字段：

```yaml
name: growth-weekly
description: 汇总本周个人成长事件并生成简报
version: 0.1.0
hooks:
  - weekly-report
permissions:
  spaces: current
  growth: read
  notes: read
tools:
  - query_notes
  - query_growth
  - write_report
```

`permissions.spaces`：`current`（默认，仅当前空间）或 `confirmed-list`（安装时用户确认的空间列表）。`write_report` 只写中枢侧报告对象，不写源。

`hooks` 在 v1 **仅允许**：`post-sync`、`on-ask`、`weekly-report`。

### 12.2 运行时

- 进程：`apps/skill-runner`，隔离运行（独立系统用户或容器）。**无源凭证**。
- 调用方下发短寿命、空间只读 token（默认 10 分钟，单 Space）。
- 超时：默认 30 秒；`weekly-report` 可到 120 秒。超时杀进程。
- 默认无外网。`tools` 或 `permissions.network` 显式声明才放行。P1 官方 Skill 不申请外网。
- 禁止访问 `Connection.secrets`，禁止写源，禁止跨 Space，除非安装时 `permissions.spaces=confirmed-list` 且用户确认。
- 输出：结构化 JSON + 可选 Markdown 报告，存中枢数据库 / 对象存储，不写回编辑器。

### 12.3 官方 Skill

| skill_id | 阶段 | hook | 说明 |
|----------|------|------|------|
| growth-weekly | P1 第一个官方 Skill | weekly-report | 只读个人空间 GrowthEvent + 相关 Note，产出周报 |
| meeting-extract | P1 可后做 | post-sync | 从新同步笔记抽会议纪要字段 |
| writing-health | P1 可后做 | weekly-report / on-ask | 写作健康度（篇幅、断更、孤岛笔记） |

P1 验收以 `growth-weekly` 能跑通为准。Skill 注册表（市场、签名、审核）是开放项，P1 允许从本地目录或对象存储前缀安装。

## 13. 权限

- **个人 Space**：仅 owner。不出现第二成员。
- **团队 Space**：`owner | editor | viewer`，见 5.3。
- **Skills 默认只当前 Space**。跨 Space 必须在安装时确认。
- **查询层硬过滤成长**：所有 `/v1/growth*` 与内部查询必须 `JOIN spaces AND spaces.kind = 'personal'`。团队 Space 的 growth 接口返回 400，错误码 `growth_personal_only`，文案「成长分析仅用于个人空间」。
- API 鉴权：P0 session cookie 或 bearer（本地账号）。所有笔记查询带 `space_id` + 成员检查。

角色能力（重申）：

| 角色 | 读笔记/预览/搜索/问答 | 管理连接 / 触发同步 | 安装/启停 Skill | 管理成员 |
|------|----------------------|---------------------|-----------------|----------|
| owner | 是 | 是 | 是 | 是 |
| editor | 是 | 是 | 否 | 否 |
| viewer | 是 | 否 | 否 | 否 |

## 17. 风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| 思源官方 S3（dejavu 加密块） | 解包失败或误把密文当正文 | v1 不解包；产品与向导标明不受支持；只引导模式 A/B |
| Obsidian E2EE | 正文不可读 | 连接标 `encrypted_unreadable`，不摄入正文 |
| 源 API 速率限制（Notion / 飞书 / 思源内核） | 同步中断、封禁 | 适配器内限流与重试；单 Note 失败不中止批次；cursor 保守推进 |
| 中文分词（CJK tokenization） | FTS 召回差 | P0 明确中文配置或 bigram 退路；P1 用向量补 |
| Markdown 块 id 漂移 | 问答锚点失效 | 思源用原生块 id；MD 用 heading+指纹；预览找不到锚点时落到篇首并记日志 |
| Skill 逃逸 | 读到源凭证或外网 | 独立进程、无 secrets、默认禁网、短寿命只读 token、超时 |
| 团队笔记漏入成长 | 隐私 / 产品错误 | 表约束 + 查询硬过滤 `spaces.kind=personal`；团队接口拒绝 growth |

## 18. 第 1 周开工顺序

不要先做四个适配器。顺序：

1. `packages/core` 类型：Space、Connection、Note、Block、Change、source_id 工具函数。
2. Postgres 迁移：User、Space、SpaceMember、Connection、Note、Block、Asset、Link、Chunk（fts 列可先建，embedding 可空）、`sync_run` / `sync_note_log`。GrowthEvent 表结构按第 5 节冻结；建议第 1 周建表、API 先不暴露。
3. MinIO + **Obsidian 明文 fixture**（小 vault：几篇 md、一张图、一个被 ignore 的 `.obsidian/`）。
4. Obsidian 适配器：`probe`、`ListObjectsV2` + ETag 的 `listChanges`、`fetchNote` / `fetchAsset`。
5. `packages/normalize`：md → blocks / links / hash。
6. `packages/preview`：canonical → HTML + `b-` 锚点。
7. worker 管道 + FTS 索引写入。
8. api：本地账号、单个人空间、connections、sync、notes、preview、search。
9. 手工跑验收：改 fixture 中一篇 md，sync 后预览与搜索在 15 分钟内更新。

## 19. 开放项（不阻塞 P0）

下列问题保持开放，**不得**因此停 P0：

1. 官方 Obsidian 插件 vs Remotely Save：P0 按 Remotely Save 风格对象键实现。若官方插件键规则不同，P1+ 加探测，不改 source_id 方案以外的管道。

### 20.1 仓库目录（已拍板）

```
apps/api
apps/web
apps/worker
apps/skill-runner
packages/core
packages/adapters
```

`packages/*` 互不依赖 `apps/*`。模块使用 ESM。TypeScript 开 `strict`。迁移 SQL 放 `apps/api/migrations/NNNN_name.sql`，api 与 worker 共用。配置走环境变量，本地用 `.env.example`，密钥不进版本库。日志为结构化 JSON，字段至少 `request_id`、`connection_id`、`note_id`、`job_id`。
